# B2: численные GPU-пробы по явному запуску

Эти скрипты запускаются вручную. Импорт entry не запускает пробу; никаких startup hooks нет. Скрипты не открывают/создают уровни, не запускают UE и не сохраняют карту. Результаты `.json` и `.rgba32f` записываются рядом со скриптами, поэтому папка должна быть доступна для записи.

Нужны UE 5.8.2 с установленным FogMS Transport и активным GPU/RHI-путём, Python Editor Script Plugin, уже открытая карта `/Game/FogMS_Test/FogMS_Box.FogMS_Box` вне PIE, ровно один `FogMS - Live Box`. Wall дополнительно требует существующий `FogMS - Pillar 1` с `/Engine/BasicShapes/Cube.Cube` и версию Transport с проверкой крайней половины ячейки (исправление Package5). Пробы не предназначены для произвольной рабочей карты.

- [Numeric](gpu_protocol.md): 11 скалярных случаев — однородная среда, white furnace, поглощение и вакуумный зазор.
- [Wall](gpu_wall_protocol.md): 3 пары без стены/со стеной толщиной 5 cm, включая крайнюю половину ячейки.
- [Receiver reconstruction](gpu_wall_reconstruction_protocol.md): отдельный опциональный GPU-проход Package6 проверяет штатный sampler на восьми позициях каждой ячейки; поток в этом дампе отсутствует.

Перед каждым прогоном задайте новый `id` в соответствующем конфиге. Примеры используют разные `numeric-repro-001` и `wall-repro-001`. Существующий receipt с тем же id запрещает повторную запись. Запускайте только одну пробу за раз; во время неё не редактируйте сцену.

`baseline_reference` необязателен: `null`, отсутствие поля или отсутствующий файл не препятствуют запуску. Существующий файл проверяется на совпадение карты и записывается в provenance. Он никогда не используется для восстановления. `baseline_status` сообщает `not_requested`, `missing_optional` или `verified_world`.

До изменений создаётся `PREPARED` receipt со свежими режимом/итерациями Box, пятью диагностическими CVars, throttle/autosave, fingerprint сцены и SHA карты. Wall также сохраняет pose и temporary-hidden всех `StaticMeshActor`. Завершение, ошибка, timeout и явная остановка пытаются восстановить это состояние. Проверяйте `restoration_ok=true` и все `restoration.checks`. Успешный ответ консоли означает принятие задания; измерения закончены только при `status=COMPLETED`.

Для остановки задайте в текущем конфиге `"action": "stop"` и снова выполните его entry-команду `py`. Для восстановления после потери Python state задайте `"action": "restore"` и `"restore_receipt": "<receipt текущего прогона>.json"`, затем повторите ту же команду в той же карте. Например:

```json
{"action": "restore", "restore_receipt": "gpu_wall-wall-repro-001.json"}
```

Восстановление использует только свежий snapshot указанного прогона и не делает неполную серию успешной. После восстановления верните `action=run` и выберите новый id. Аварийное завершение процесса не может выполнить `finally`; durable receipt остаётся для восстановления.

Обычный offline-анализ требует Python и NumPy, а также соседний `../transport_reference.py`. Порог ошибки J/остатка/баланса потока — 1%; все четыре atlas slabs проверяются отдельно, timestamps и SHA payload сверяются. CPU-эталон использует ту же дискретизацию из шести направлений. Это проверка численного GPU-оператора на скалярных fixtures, а не подтверждение угловой точности произвольной сцены, качества Lumen boundaries, RGB-албедо или производительности. Отдельный reconstruction-анализатор проверяет утечку sampler и не оценивает поток. Readback намеренно останавливает GPU; elapsed time не является pass timing.

Копии сохраняют проверенную последовательность capture/restore и уравнения обычных анализаторов. Отличия: пути относительно `__file__`, необязательный baseline, защита entry от запуска при импорте, новые example ids и эта документация. Wall включает исправление UE Python API: установка pose через Actor setters, без отсутствующего `MathLibrary.make_transform`. Дополнение reconstruction явно выбирает иную схему fourth slab, сохраняет/восстанавливает `r.FogMS.Transport.TestReconstruction` и использует отдельный анализатор. Обычный wall-конфиг оставляет `reconstruction_test=false`. SHA исходных файлов сохранены в [PROVENANCE.json](PROVENANCE.json); исходные receipts не переносятся и не перезаписываются.
