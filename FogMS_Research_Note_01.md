## 2. Поправки к выводам аудита

### 2.1 Риск №3 («надо делить на σs → A2 только на отдельном буфере») — неверно. DERIVED

Gather оперирует **source term q**, а не входящей яркостью. Яркость, приходящая в точку x с направления ω:

`L(x, ω) = ∫ T(x, s) · V(x, s) · q(x + s·ω) ds`

— тот же интеграл, что делает `FinalIntegrationCS` для камеры. Делить на σs не нужно. Вторичный источник:

`q_MS(x) = σs(x) / 4π · ∫_Ω L(x, ω) dω`

где `σs(x)` = **текущий** `VBufferA.rgb` (привязан), `q` = `LightScatteringHistory.rgb` с поправкой экспозиции как в 1177–1179.

Размерности: q [яркость/см] → ∫ds [яркость] → ∫dω [яркость·ср] → ×σs/4π [1/см/ср] → [яркость/см]. Сходится.

Следствие: **A2 в оверлее при g = 0 размерно корректен** (фаза = 1/4π, константа, история изотропна). Реальные ограничения A2: фаза при g ≠ 0 (см. 2.3), лаг `1 − β + β·k`, нули за `ConservativeDepth`, отсутствие occlusion.

### 2.2 Emissive и инвариант 2. DERIVED

Emissive без σs — физически корректно: эмиссия — отдельный источник в уравнении переноса. Инвариант переформулировать: **«при σs = 0 вклад MS равен нулю»** (а не «нет света»). В тестовой сцене emissive = 0 — верно. В пространственном режиме эмиссия **должна** рассеиваться как любой источник (она уже сидит в истории — это правильно).

### 2.3 Величина фазовой ошибки истории. DERIVED

Отношение `p_HG(θ) / (1/4π)` — во сколько раз история искажает изотропный источник:

| g | взгляд на источник | сбоку (90°) | от источника |
|---|---|---|---|
| 0.2 | 1.88× | 0.91× | 0.56× |
| 0.6 | 10× | 0.40× | 0.16× |

При g ≤ 0.2 — терпимо для эксперимента, при g ≥ 0.5 — непригодно. Для нескольких источников «разделить обратно» нельзя (аудит прав).

### 2.4 Оценка патча «5 строк + include» занижена. DERIVED

Нефазированный источник требует второй цели накопления **и в `InjectShadowedLocalLightPS/RGS`** (там фаза тоже применена до суммы), плюс создание ресурса и привязки. Порядок — десятки строк в 3 шейдерах и C++. Оценку в §8.6 аудита поправить.

## 3. Спецификация A1 — самозатенение directional

### 3.1 Модель. DERIVED

`ShadowFactor *= exp(−(τ_in + τ_out))`

- `τ_in` — марш по `VBufferA.a` внутри froxel-сетки.
- `τ_out` — аналитический интеграл height fog от точки выхода из сетки до `S_max`.

### 3.2 Почему обрыв марша на границе недопустим. DERIVED

Плотность есть только во фрустуме. Взгляд на солнце → луч к солнцу долго идёт внутри сетки → большая τ. Взгляд от солнца → луч сразу выходит (через near/бок) → τ ≈ 0. Самозатенение **зависит от поворота камеры**, критерий 4 из §13 аудита проваливается по построению даже в чистом height fog. `τ_out` обязателен в A1.

### 3.3 τ_in — марш

- Шаги в мировом пространстве от центра froxel вдоль `L` (к источнику). Распределение неравномерное: `s_k = S_march · ((k + ξ)/N)²`, выборка в середине интервала, `Δs_k = s_{k+1} − s_k`. `ξ` — покадровый джиттер (переиспользовать существующий Halton/frame random), шум гасит штатная история.
- На каждой выборке: world → UVW сетки (существующие функции репроекции), трилинейный `VBufferA.a`. Если UVW ∉ [0,1]³ — марш прекращается, точка выхода `p_exit` передаётся в `τ_out`. Сетка выпуклая — повторного входа нет.
- `N` и `S_march` — defines. Ориентиры: N = 8/16 realtime, 32–64 Max; `S_march` ≈ `VolumetricFogDistance`.
- Если марш дошёл до `S_march`, не выйдя из сетки, — `τ_out` считается от последней точки.

### 3.4 τ_out — аналитика. DERIVED, сверить с кодом

Для слоя i: `ρ_i(z) = D_i · 2^(−F_i·(z − H_i))` (exp2 — как в `MaterialSetupCS` 169–171). Вдоль луча `z(s) = p_z + s·L_z`:

`∫_0^S ρ_i ds = ρ_i(p_z) · (1 − 2^(−F_i·L_z·S)) / (F_i · L_z · ln2)`

- при `|F_i·L_z·S·ln2| < 1e−3` → предел `ρ_i(p_z) · S`;
- `S = S_max` (define; ориентир 10–20 км — заменяет кривизну Земли, иначе на закате T → 0).

`τ_out = k · Σ_i ∫`, где `k` — **ровно те же** множители, что в `MaterialSetupCS` 176–178 (`0.5`, `GlobalExtinctionScale`, поведение при `PROJECT_EXPFOG_MATCHES_VFOG` — в проекте режим включён). Не использовать `CalculateLineIntegralShared` вслепую: у экранного height fog могут быть другие множители. `HeightFogCommon.ush` **не редактировать** (полная перекомпиляция материалов).

### 3.5 Следствие: глобальное потемнение. DERIVED + DECISION

Пример: FogDensity 0.05, falloff 0.2, солнце 10° → τ_out ≈ 1.0 → T ≈ 0.35 на уровне высоты тумана (при дефолтной плотности 0.02: τ ≈ 0.42, T ≈ 0.66). Физично, но поверхности UE так солнце не ослабляет → заказчик увидит «туман потемнел».

Нужен define-переключатель `FOGMS_EXCLUDE_GLOBAL_LAYER`: `τ_eff = max(τ − τ_ref, 0)`, где `τ_ref` — полностью аналитическая τ height fog из той же точки. Тогда чистый height fog выглядит как vanilla, а тени дают только LFV / volume-материалы / неоднородности. **Решено заказчиком: дефолт = 0 (физичный режим).** Переключатель остаётся как инструмент для шовного теста и будущей арт-коррекции.

### 3.6 Что A1 не покрывает (записать как ограничения)

- LFV и volume-материалы **вне фрустума** не затеняют (их плотности там нет).
- Плотность за `ConservativeDepth` — см. Q5.
- Локальные источники, sky/Lumen-ambient — без самозатенения.

### 3.7 Критерии приёмки A1 (замена §13 аудита, ≤7)

1. Все defines = 0 → рендер побитно совпадает с vanilla. Патченный `VolumetricFog.usf` компилируется **во всех пермутациях**, включая `MegaLights` и `Ubershader` (заказчик их не использует, но оверлей пересобирает все).
2. **Шовный тест:** сцена только с height fog. Debug-вид `|τ_in + τ_out − τ_ref|` ≈ 0 по всему экрану (допуск задать, ориентир ≤ 5% от τ_ref). Проверяет единицы, длины шагов, репроекцию и множители разом.
3. Debug-виды: Extinction (`VBufferA.a`), Transmittance `exp(−τ)`, Seam error; переключение через `View.GeneralPurposeTweak`.
4. Поворот камеры на 360° в статичной сцене с height fog: яркость тумана в фиксированной мировой точке не меняется заметно (оценивает заказчик + debug Transmittance).
5. `FOGMS_EXCLUDE_GLOBAL_LAYER = 1` в чистом height fog → визуально vanilla.
6. `ProfileGPU` для `LightScattering` при N = 8/16/32 (снимает заказчик).
7. Локальные источники не затронуты — записано как ограничение.

### 3.8 Совместимость с MegaLights — отложено, дверь не закрывать. DERIVED из аудита §3.2

Заказчик MegaLights **не использует**, но хочет иметь возможность добавить позже. Сейчас кода под MegaLights не пишем; соблюдаем правила, которые не дадут зайти в тупик.

Что зависит от пути света, а что нет:

| Часть FogMS | Зависит от MegaLights? | Почему |
|---|---|---|
| Пространственный MS (A2 / B) | **Нет** | читает суммарный source term из истории; `MegaLightsVolume` входит в `L_total` до `·σs` (1157) наравне с остальными |
| Самозатенение и октавы directional (A1 / A1b) | Только при `r.MegaLights.DirectionalLights = 1` | тогда ветка directional в `LightScatteringCS` пропускается (941) и наш код просто не исполняется — безопасный no-op, записать как ограничение |
| Самозатенение локальных источников (будущее) | **Да** | `MegaLightsVolume` — уже сложенная сумма; per-light τ надо применять внутри MegaLights volume shading |

Правила проектирования с A1:

1. **Марш τ, τ_out и октавы — отдельные чистые функции** в своём include оверлея (например `FogMS_Common.ush`): вход — мировая позиция, направление/позиция источника; никаких обращений к локальным переменным ветки directional. Тогда их можно вызвать из инжекций локальных источников или из MegaLights volume shading без переписывания.
2. **Источник плотности — за макросом** (`FOGMS_SAMPLE_EXTINCTION(uvw)`). Причина: `RenderMegaLights` (3471) исполняется **раньше** `ComputeVolumetricFog` (3660) — в момент оценки MegaLights-источников `VBufferA` текущего кадра ещё не существует. Будущий путь сможет подставить σt прошлого кадра (`LightScatteringHistory.a`) вместо `VBufferA.a`, не трогая математику.
3. Никаких предположений «`USE_MEGA_LIGHTS` всегда 0»: все вставки под `#if`-охраной должны компилироваться при любом его значении (критерий 1).
4. Вклад `MegaLightsVolume` в A1/A1b **не масштабировать и не затенять** — он остаётся как есть.

Стоимость будущего подключения (оценка): C++-привязка плотности к MegaLights volume shading или патч движка — тот же класс работ, что самозатенение локальных источников. Уточняется по Q8.

## 4. A1b — октавы. DERIVED

Следовать конвенции Epic (три параметра, знакомые художникам по облакам): contribution `a`, occlusion `b`, eccentricity `c`, самоквадрирование по октавам (`VolumetricCloud.usf` 390–393, 424–428):

`j_dir = E · Shadow_geo · Σ_m σs · A_m · exp(−τ · B_m) · P_m`
`A_0 = B_0 = 1, P_0 = HG; A_{m+1} = A_m · a_m, a_{m+1} = a_m²` (аналогично B, b); `P_m = lerp(Iso, HG, C_m), C_{m+1} = C_m²`.

- τ — полная из A1 (с учётом выбранного режима 3.5).
- M ≤ 3. Это **арт-модель, не физика**: энергию ограничивает только clamp на `a`. В документации так и назвать.
- Применяется только к directional. Ambient (Lumen SH) не трогать.
- Режим взаимоисключающий с A2/B (`FogMS_HANDOVER.md` §4 п.4) — один define-enum, не два булевых.

## 5. Ветка «этап B без патча движка». HYPOTHESIS

Аудит подтвердил составные части: хук `PostTLASBuild` с флагом inline RT; публичный TLAS (`FXRenderingUtils.h:89`); volume-материалы аддитивно пишут Emissive в `VBufferB`, а `VBufferB` входит в source term до интегрирования (1169) **без σs** — то есть это легальный вход «готового source term».

Предполагаемый конвейер:

```
[кадр N, PostTLASBuild]  RDG-compute плагина, inline RT:
    вход: LightScatteringHistory(N−1): rgb = q, a = σt
    считает q_MS на своей грубой сетке, V через TLAS, несколько итераций
    σs(приёмник) ≈ albedo_global · σt   (ошибка для цветных LFV — принять)
    выход: volume render target

[кадр N, ComputeVolumetricFog]  volume-материал (большой бокс плагина):
    Extinction = 0, Emissive = sample(q_MS) → аддитивно в VBufferB
    → LightScatteringCS добавляет до интегрирования
```

Обратная связь: история уже содержит прошлый q_MS → неподвижная точка `L = j₁ + K·L`; для внутренних итераций нужен `j₁ ≈ H − q_MS_prev` (плагин хранит свою копию с тем же blend 0.9). Фазовая ошибка 2.3 остаётся — ветка честна только при малых g.

Два блокирующих неизвестных — Q1 и Q3 ниже.

## 6. Идея вне плана: мягкие RT-тени в тумане. HYPOTHESIS

`InjectShadowedLocalLightRGS` — глобальный шейдер в `VolumetricFog.usf`, луч идёт в центр источника (жёсткая тень). Джиттер цели луча по форме источника (SourceRadius / rect extents) + штатная история → мягкая объёмная тень, согласованная с полутенью на поверхностях. Только оверлей. Проверить, какие данные источника доступны в RGS. Не входит в A1.
