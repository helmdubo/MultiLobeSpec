**Статус:** пакет собран, проверен на D3D12/SM6 и установлен в основной MimirHead. **Визуальная приёмка A1c не пройдена:** пользователь сообщил о сильном мерцании indirect и недостаточной детализации. Прежние статические HDR-проверки подтверждают действие ослабления, но не приемлемую стабильность в обычном viewport. Плотность, Perlin, transform и настройки A1b сохранены. ## Обратная связь и следующий срез — 2026-09-20

Read-only проверка открытого `/Game/FogMS_Test/FogMS_Box`: fog grid pixel size 8, Z=64; Lumen TLV pixel size 32, tracing octahedron resolution 3 (9 направлений на probe за кадр), SpatialFilter=0, RadianceCache=0. Temporal reprojection и jitter включены у обоих путей, HistoryWeight=0.9. Пользовательские Indirect Shadow Steps=32 и Density Channel=B сохранены. 32 шага повышают точность интеграла вдоль луча, но не число направлений освещения. Receipt: `E:/GITHUB/MultiLobeSpec/.codex-build/FogMS_A1c_Feedback_20260920/current-result.json`.

Fog читает текущий TLV, после чего использует собственную fog history; temporal history TLV этот вход не фильтрует. Отсутствие spatial filter и малое число направлений — кандидаты на источник шума, не доказанная единственная причина. Численные проверки `LightingFixed` выполнялись с фиксированным jitter: они не являются тестом мерцания.

Read-only аудит также выявил условный дефект: family-dependent admission/strength сравнивается с общим snapshot мира и отправляется в общий GPU packet. При чередовании допустимых/недопустимых view families возможны повторные reset и использование последнего packet всей группой. Наличие такого чередования в текущем viewport пока не измерено. Наш reset расположен после native выбора history-miss supersampling, поэтому сбрасываемый кадр не получает его дополнительные выборки. Для стабильного одиночного view постоянный reset не подтверждён.

Следующий срез: (1) измерить причины reset и покадровую вариацию при неподвижной/движущейся камере; исправить изоляцию view/history и исследовать фильтрацию уже ослабленного indirect; (2) в той же карте раздельно проверить предел разрешения плотности, fog grid и TLV с GPU-стоимостью; (3) после этого добавить управляемую detail/erosion Volume Texture, согласованную между видимой плотностью и всеми FogMS-маршами. Если нужная чёткость не достигается в допустимом бюджете froxel grid, сначала пересмотреть способ визуализации локального объёма. Пространственный MS остаётся отдельным последующим этапом; A1c сам не переносит рассеянный свет. Новых уровней и изменений Engine не требуется для диагностики; доступность будущих renderer hooks должна быть проверена до обещания реализации.

## Что делает A1c

A1c ослабляет входящую радиацию Lumen на пути через авторскую плотность нашего Box. Для каждого используемого Lumen-луча берутся его фактическое направление и расстояние до принятого пересечения с поверхностью:

```text
tau(ray) = integral sigma_t(x + s * direction) ds
T(ray) = exp(-tau(ray))
L_fog(ray) = L_native(ray) * lerp(1, T(ray), Strength * BoxWeight(x))
```

Интегрируется только пересечение конечного отрезка с Box. При попадании в поверхность путь заканчивается на ней; при уходе в небо — на выходе из Box, если допустимая дальность трассировки покрывает этот путь. Поэтому близкий эмиссив внутри среды не должен терять свет так, словно тот прошёл через всю толщину облака до неба. Нулевая плотность или длина дают T=1.

Это **incoming attenuation, не пространственное multiple scattering**. A1c не переносит рассеянный свет между соседними ячейками, не заполняет геометрическую тень таким переносом и не возвращает влияние тумана в Lumen surface cache. A1b Octaves остаётся отдельным художественным приближением directional scattering.

По исходникам A1c создаёт второй SH accumulator только для текущего выхода Volumetric Fog. Штатный `Lighting`, его нормировка, Lumen history и выход для translucent surfaces/Heterogeneous Volumes сохранены. На пути тумана sigma_s по-прежнему применяется штатно один раз; геометрическая видимость повторно не умножается. Directional A1/A1b, локальные источники, собственная Volume Material Emissive и extinction не являются целями этого патча. **GPU-регрессия этих инвариантов ещё не выполнена.** Сам fog temporal filter остаётся штатным; изменения эффективных controls/плотности используют существующий per-view reset, включая поздний persistent SceneCapture.

## Протокол для пользователя

Выполнять после сообщения об успешной установке A1c; текущая редакция такого сообщения не заменяет.

1. Открыть прежний **FogMS_Box**, выбрать **FogMS - Live Box**, раскрыть **FogMS → Indirect**. Оставить один включённый и видимый FogMS Box, `Enabled=true`, `Density Enabled=true`, с допустимой Volume Texture. Сохранить текущую камеру, экспозицию, плотность и Scattering Mode для сравнения.
2. Нажать **Enable Indirect Preview**. Кнопка включает эксперимент для текущей сессии, задаёт поддерживаемые Lumen settings и применяет shader overlay. Дождаться окончания компиляции. Одного флажка Indirect Shadowing до этой кнопки недостаточно. У текущего view должен появиться **Indirect Shadow Status = Active experimental ray attenuation**. Если поле показывает конкретную причину bypass, сначала устранить её; одинаковые картинки в bypass не подтверждают работу A1c.
3. Для A/B переключать **Indirect Shadowing** либо **Indirect Shadow Strength: 0 → 1**. После первоначальной компиляции эти изменения live, без Apply. При Strength=0 ожидается статус **Ready (Strength=0: native indirect lighting)**, при выключенном флажке — Off. Оба состояния должны возвращать исходное освещение тумана **при тех же preview renderer settings**. Не нажимать Restore Standard Lumen между половинами такого A/B: она меняет и базовый Lumen.
4. В sky-контроле сравнить освещение внутри достаточно толстого Box при Strength=0/1, не меняя Density между половинами пары. Затем повторить пару при большей плотности. Ожидается более заметное ослабление непрямого света при росте оптической толщины. Для чистого sky-контроля физическая интенсивность солнца и emissive должна быть нулевой; одного отключения directional fog scattering недостаточно для удаления surface bounce. Существующий исследовательский Sky Light использует cubemap; это не отдельная приёмка динамического SkyAtmosphere.
5. Во внутреннем emissive-контроле оставить видимую Lumen светящуюся поверхность внутри Box, временно убрать физический вклад Sun/Sky. Сравнить ближнее и дальнее расположение по отношению **On/Off для каждого расположения**, при неизменных остальных controls. Для однородной среды короткий путь должен сохранять больше входящего света. Не сравнивать только абсолютную яркость двух положений: меняются телесный угол и распределение Lumen-лучей. Измеряемый участок тумана не должен содержать прямое изображение эмиттера. Нулевой сигнал в обеих половинах означает отсутствие пригодного контроля, а не успешную проверку затенения.
6. Проверить live движение/поворот Box и возврат Strength=0/Off. Старое затемнение не должно оставаться после восстановления исходного состояния. Далеко вне Box ожидается прежнее освещение; узкую область около его края оценивать с учётом интерполяции TLV, описанной ниже.
7. Для завершения нажать **Restore Standard Lumen** и дождаться перекомпиляции. Кнопка выключает Indirect Shadowing, переприменяет overlay без A1c TLV patch, ждёт shader compilation/GPU, затем восстанавливает сохранённые при включении preview CVar. Последующие ручные изменения этих CVar сохраняются, если значение уже отличается от preset. Density и directional FogMS остаются отдельными controls. При ошибке Apply preview renderer settings сохраняются, в Output Log появляется причина; завершённый restore в таком случае не заявляется.

Провал проверки — NaN/чёрные блоки, изменение extinction только от Indirect Shadowing, устойчивый след прежних controls, потеря близкого emissive из-за интегрирования за его поверхностью, эффект далеко вне Box или изменение translucent/HV при одинаковой renderer-конфигурации. Разницу сначала сравнивать с повтором той же неподвижной сцены: кадры Lumen могут различаться даже при отключённом fog jitter.

## Проверка плотности и debug

`FogMS.Debug 1` показывает native sigma_t: фон height fog плюс локальная плотность. `FogMS.Debug 4` показывает только авторскую плотность Box, которую читает A1c. Масштаб одинаковый: `saturate(sigma_t[1/cm] * 10000)`, с последующим PreExposure. Это локальное значение у глубины изображения, не интеграл луча камеры.

Для Debug4 требуется `Indirect Shadowing=true`; **Strength=0** оставляет поле доступным, не меняя освещение. Сравнивать внутри ядра Box, перед непрозрачной контрольной поверхностью и ближе **0.6 × Fog View Distance**. Sky-depth за Box не подходит. Из Debug1 предварительно вычитается baseline с black Volume Texture, чтобы убрать height fog. При white texture и Density=.005 1/м ожидаемый ненасыщенный вклад Box — .5 при PreExposure=1. В Debug1 это .5 плюс фон до насыщения. Для Perlin возможен остаток от native froxel filtering и depth-constrained voxel sampling; универсальный допуск заранее не назначен.

Закончить командой `FogMS.Debug 0`. Само включение A1c не должно менять Debug1. Debug4 служит сверкой UVW/channel/threshold/softness/feather, включая отрицательный и неравномерный масштаб; пройденная CPU-геометрия ещё не доказывает GPU-соответствие материалу.

## Границы прототипа

- **Платформа и режим:** UE 5.8.2 CL 56702186, один GPU, D3D12/SM6, `-BindlessAll`, `r.RayTracing=1`, Lumen GI у проверяемого view. Для SceneCapture также разрешён ray tracing. Один включённый видимый Box. Cooked/source-stripped textures и Shipping этим срезом не поддержаны/не проверены.
- **Preview settings:** кнопка задаёт `r.Lumen.HardwareRayTracing=1`, `r.Lumen.TranslucencyVolume.HardwareRayTracing=1`, `r.Lumen.TranslucencyVolume.Enable=1`, `TraceFromVolume=1`, `RadianceCache=0`, `ShareRadianceCacheWithOpaque=0`, `SpatialFilter=0`, `GridCenterOffsetFromDepthBuffer=-1` (последние пять — в пространстве `r.Lumen.TranslucencyVolume`). Дополнительно **`r.Lumen.AsyncCompute=0`**; принудительный `r.RDG.AsyncCompute>1` запрещает эксперимент. Эти настройки меняют и native Lumen, поэтому их фиксируют на всё A/B. Bindless payload отсутствует среди RDG-параметров прохода; поддерживаемая синхронизация пока ограничена graphics queue.
- **Достоверный endpoint:** Post Process **Lumen Skylight Leaking=0** у проверяемого view. Полная диагональ Box должна быть меньше `min(65000 см, LumenMaxTraceDistance × r.Lumen.TraceDistanceScale)`. Runtime отказывает при нарушении. Ограничение учитывает R16F hit distance; усечённый sky miss нельзя засчитывать как путь через всю среду. Radiance cache, spatial filter и depth-dependent trace origin пока исключены, поскольку смешивают radiance или нарушают восстановление нужного луча/endpoint.
- **Авторское поле:** используется собственная Volume Texture Box через отдельный resident 2D atlas, а не ещё не существующий на этом этапе VBufferA. Height fog, native LFV и чужие Volume materials не входят в integral A1c. Выборка поля возможна вне фрустума; camera fade native voxelization не переносится в это авторское поле. Старые ограничения directional A1 за фрустумом этим не исправлены.
- **Texture contract:** один volume source/layer/block **BGRA8**, sRGB Off, **VectorDisplacementmap** compression; готовый platform mip0 **PF_B8G8R8A8** того же размера. Цветовые/alpha adjustments должны быть исходными, Flip Green Channel выключен. Каждая ось **1..256**, дополнительно **SizeY × SizeZ ≤ 16384**: 256³ не поддерживается. Atlas имеет размер X × (Y·Z), хранит исходный mip0 и вручную воспроизводит trilinear wrap. Невалидная/компилирующаяся текстура выключает A1c с причиной, без подстановки однородной плотности. Исходный Perlin asset для обхода ограничения менять не требуется.
- **Lifetime:** atlas и Box packet удерживаются runtime; старые atlas allocations освобождаются после GPU fence. Наличие descriptor index само по себе не считается доказательством residency. GPU swap/eviction/stress-проверки остаются PENDING.
- **Граница TLV:** вес A1c вычисляется в ячейках Translucency Lighting Volume. Внешние ячейки записывают native lighting, внутренние — ослабленный результат, а последующая trilinear выборка создаёт переходную полосу вокруг Box. Это не точная геометрическая граница в каждом пикселе; ширина зависит от TLV resolution и view. Проверка «вне Box без эффекта» должна брать область за поддержкой соседних ячеек. Качество у малого Box, SH ringing, цветовая компрессия SH и утечки возле границы требуют отдельной GPU-оценки.
- **Стоимость:** Indirect Shadow Steps=16 по умолчанию, допустимо 1..64. Работа растёт с числом активных TLV-ячеек, Lumen-лучей и шагов среды; при octahedron resolution=3 это девять лучей на ячейку. Полный штатный Lumen dispatch сохраняется. Стоимость A1b не является оценкой A1c.
