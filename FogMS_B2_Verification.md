# FogMS B2 — проверка в проекте

Открыть существующую `/Game/FogMS_Test/FogMS_Box`, выбрать **FogMS - Live Box**.

1. Details → FogMS → Scattering → **Scattering Mode = Transport (B2)**. `Transport Iterations = 24`.
2. `Spatial Status` должен быть **Active B2 isotropic transport**. Изменения применяются живьём; Apply для переключения режима не нужен. Если статус сообщает ограничение, это fallback, а не результат B2.
3. Для сравнения вернуть **World (Current Frame)** — предыдущий B1. Положение, размер, Perlin, Density и Albedo при этом не менять. **Off (A1 Only)** выключает дополнительное MS; прежнее самозатенение A1 остаётся. `Enabled=false` выключает FogMS освещение, сохраняя отдельную авторскую плотность; скрытие актёра скрывает и сам объём.
4. В B2 `Spatial Strength`, `Spatial Distance` и `Indirect Shadow Strength` не управляют яркостью. Они сохранены для B1. Уменьшать эти поля до .5 для нового режима не требуется. Albedo задаёт долю рассеяния, Density — оптическую толщину.

Проверять в активном окне UE с realtime viewport. При штатном `Use Less CPU when in Background` неактивное окно получает native Background Process override, и статус может показать `World requires one realtime view.`. Сохранённая настройка пользователя не изменена; дождитесь нескольких кадров после возвращения фокуса. Скриншоты для сравнения делать обычным viewport capture: HighResShot для этого среза переводит view в неподдерживаемый non-realtime путь.

## Что смотреть

- Освещение тёмной части должно получать вклад от освещённой части среды. При закрытии всех источников облако само не создаёт свет.
- Повернуть солнце и посмотреть на границы теней колонн. Перенос не должен протекать через сплошную преграду; обход края преграды через открытую среду допустим.
- Подвигать/приблизить камеру, изменить FOV. Проверить отсутствие прежнего накопления света после остановки. Native Lumen, temporal fog и финальное разрешение камеры всё ещё могут давать собственные изменения; мировое поле B2 не использует fog history.
- У существующего Spot поменять интенсивность. При изолированном источнике линейный HDR вклад должен масштабироваться вместе с ним. Экранный LDR после tone mapping не обязан выглядеть «вдвое ярче».
- Сравнить 24 и 64 iterations. Существенная разница указывает на недостаточную сходимость 24; это не настройка внешнего вида. При высокой Density/Albedo=1 обязательно проверить.
- Resize Box не должен менять world scale шума. Движение/эволюция самой density texture пока не реализованы.

Не считать провалом сам по себе более светлый B2: в B1 каждый дополнительный порядок умножался на .35 и обрывался после трёх добавленных порядков/короткого пути. Провал — NaN/вспышки, самосвечение при действительно нулевых источниках, исчезновение density при lighting fallback, неснимаемый эффект скрытого Box, явная утечка через проверяемую сплошную стену или большой рост света при 24→64.

## Численные проверки

В Output Log можно выгрузить текущую сетку:

```text
FogMS.DumpSpatial E:/FogMS_B2_Field
```

Появятся `.json` и `.rgba32f`. Для обычного B2 JSON должен иметь `domain=transport`, `finite=true`, `iterations=24`, свежие renderFrame/sourceProducedRenderFrame. `relativeFluxDefect` относится только к дискретному diffuse balance; `maxRelativeCellResidual` — локальная невязка. Они не измеряют точность угловой квадратуры. `missingSurfaceBoundarySamples` показывает недоступные Lumen surface-cache samples.

Автоматические furnace/vacuum/wall проверки и восстановление — `Tools/FogMSEnergyValidation/B2Probe/README.md`. Запускать при неподвижном viewport, не сохранять карту во время fixture. Не использовать diagnostic `r.FogMS.Transport.Test*` для художественной настройки. После теста `Test=0`, `TestReconstruction=0`.

Известные пределы, единицы, производительность и raw evidence описаны в `FogMS_B2_Report.md`. Это проверяемый изотропный дискретный срез; полное физическое совпадение с UE Volumetric Cloud ещё не заявляется.
